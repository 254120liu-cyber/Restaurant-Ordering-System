## 发给组员的话

请在自己的分支按模板实际操作，填写姓名、环境、步骤、结果和日期。记录发现的问题及证据位置，完成后提交并发起合并请求。可以先使用可执行交付包验收，再提交Markdown记录。

## 组员操作

```powershell
git clone https://github.com/mubukuiyuan/Restaurant-Ordering-System.git
cd Restaurant-Ordering-System
git config user.name "自己的姓名"
git config user.email "自己的GitHub邮箱"
git switch main
git pull --ff-only origin main
git switch -c review/waiter-kitchen
# 完成实际验收并编辑本人记录
git add docs/reviews/waiter-kitchen.md
git commit -m "记录服务员与后厨流程实测结果"
git push -u origin review/waiter-kitchen
```

将分支和文件替换为自己负责的项目。向原仓库推送需要协作者权限，没有权限时Fork后提交Pull Request。

## 集成与导出

main保存经过测试的版本，dev用于后续集成。合并review分支后重新执行测试并导出Git历史。

```powershell
git switch main
git pull --ff-only origin main
git merge --no-ff origin/review/waiter-kitchen
.venv/Scripts/python.exe -m pytest tests/test_domain.py -q
git push origin main
powershell -ExecutionPolicy Bypass -File scripts/export-git-log.ps1
```

撤销已经共享的错误提交使用git revert，再测试并推送。所有组员完成验收后再创建最终答辩标签。自动测试与组员手工验收分别记录。
