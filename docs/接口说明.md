# 餐馆点菜系统接口说明

TCP/TLS默认连接127.0.0.1的18765端口，客户端校验证书与localhost主机名。每个UTF-8 JSON消息以LF结束，单帧上限64 KiB。同一连接串行请求，断线重新登录。

## 公共格式

请求含type、request_id、data。request_id为1～64位字母、数字、下划线、点或短横线，data为对象。ID与数量为正整数，金额为两位小数字符串。时间为带+08:00时区的ISO 8601字符串。

```json
{"type":"preview_bill","request_id":"cashier-001","data":{"order_id":1}}
{"request_id":"cashier-001","code":0,"msg":"成功","data":{"order_id":1,"total_amount":"56.00","quote_version":4,"items":[{"item_id":1,"dish_id":1,"dish_name":"宫保鸡丁","quantity":2,"price":"28.00","subtotal":"56.00","status":"已出菜"}]}}
```

## 业务入口

| type | 角色 | data输入 | 成功返回 |
| --- | --- | --- | --- |
| login | 全部 | username、password | employee_id、name、role |
| logout | 全部 | 空对象 | 空对象 |
| list_tables | 服务员 | 空对象 | tables与当前订单 |
| open_table / clear_table | 服务员 | table_id | 桌台记录 |
| create_order | 服务员 | table_id | table_id、空草稿items |
| list_dishes | 服务员 | 可选keyword、category_id、page、page_size | items、total、categories |
| submit_order | 服务员 | table_id、items，每项dish_id和quantity | 订单、order_items、total_price、version |
| add_item | 服务员 | order_id、dish_id、quantity | 更新后的订单与明细 |
| remove_item | 服务员 | order_id、item_id、reason | 更新后的订单与明细 |
| list_kitchen_orders | 后厨 | 可选page、page_size | orders、total，含桌号与明细 |
| accept_order | 后厨 | order_id | order_id、status |
| start_item / mark_served | 后厨 | order_id、item_id | order_id、item_id、status |
| preview_bill | 收银员 | order_id | items、total_amount、quote_version |
| settle_bill | 收银员 | order_id、quote_version、paid_amount、pay_method | bill_id、应收、实收、找零、支付方式与时间 |
| get_order_status | 服务员、收银员 | order_id | 订单与items，收银员另返回bill |
| manage_dish | 管理员 | action、dish_id、fields、可选分页 | 菜品记录或items、total |
| manage_category | 管理员 | action、category_id、fields、可选分页 | 分类记录或items、total |
| manage_employee | 管理员 | action、employee_id、fields、可选分页 | 员工公开记录或items、total |

列表默认page=1、page_size=20，单页上限100。后厨界面每页10个订单。create_order只校验草稿前置条件，submit_order才首次入库，桌台已绑定订单时拒绝再次提交。

管理action为list/create/update/delete。create无需ID，update/delete必须给ID。菜品可写dish_name、category_id、price、status、description。分类可写category_name。员工可写username、password、name、role、phone、enabled。重设密码需8～128字符，修改员工时省略password可保留原密码。员工响应省略密码。

角色为服务员、后厨、收银员、管理员。支付方式为现金、扫码、刷卡。现金允许找零，扫码与刷卡实收必须等于应收。

## 错误与重试

| code | 含义 | 处理 |
| --- | --- | --- |
| 0 | 成功 | 展示结果 |
| 400 | 格式、字段或支付金额非法 | 修正输入 |
| 401 | 登录无效或停用 | 重新登录 |
| 403 | 无权限 | 使用相应角色账号 |
| 404 | 数据不存在 | 刷新 |
| 409 | 状态冲突、报价过期、重复结账或引用限制 | 查询状态并核对 |
| 503 | 数据库不可用或锁冲突 | 查询状态后决定重试 |
| 500 | 其他内部异常 | 保留请求编号并查看日志 |

超时后关闭原连接，重新登录并查询get_order_status的bill。存在账单时按已保存结果处理，否则重新预览并核对现场实收。request_id只关联响应与日志，业务状态和唯一约束负责重复操作保护。

## 内部调用与事务

ClientHandler.serve调用RequestRouter.dispatch，路由器每次查询员工当前角色和启用状态。DatabaseHelper.transaction统一管理授权与业务操作的事务。OrderService负责桌台与订单，KitchenService负责接单制作出菜，BillingService负责预览结账与状态，MenuService和EmployeeService负责管理。

写事务采用READ COMMITTED，预览和状态查询采用REPEATABLE READ一致快照。需要同时锁桌台和订单时先桌台后订单。账单order_id唯一，插入账单和更新订单必须同事务，异常全部回滚。
